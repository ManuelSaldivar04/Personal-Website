StickMan Math

Educational Math Game to Help Children Learn Basic Arithmetic

Description

StickMan Math was created by me and a few friends of mine at University for a semester-long project class. The goal of the project was to create an educational/helpful game or tool for the public to use. We decided to create a Pokémon/Mario style adventure game to teach children in a fun and educational manner the 4 basic arithmetic skills.

Features

The game is designed in an advance-by-progress style, ensuring players master the previous levels before reaching the next. Each "world" targets one of the 4 principle arithmetic operations. Players can purchase items in the shop with gold earned by defeating bosses. Items help players advance through levels, rewarding good performance.

To defeat each level's boss, players must answer math problems correctly within a time limit to deal damage to the enemy. Incorrect answers reduce the player's health. If the player loses all health before the enemy, they lose the match and cannot advance. Upon defeating an enemy, players receive gold and advance to the next level.

Book Reading Organizer

App to Organize Books Read and Books Wishing to Read

Description

Developed a C++ book organizer application at Western University to master Object-Oriented Design & Analysis (OODA) principles. Prioritized architectual scalability and maintainability over UI, implementing core functionality for managing books, reviews, and ratings within a rigorously modeled domain. Applied OODA methodology end-to-end from UML diagrams to implementation, to ensure a clean, entensible foundation.

Features & OODA Implementation

• Domain Modeling via UML Class Diagrams: Established object relationships including Book-Review aggregation (1-to-many composition) and User-List associations with strict encapsulation

• Workflow Validation with Sequence Diagrams: Modeled critical operations like "Move Book Between Lists" and "Add Review" to ensure SOLID-compliant interactions

• Use Case-Driven Development: Formalized 10+ scenarios including priority-based sorting and wish list management with preconditions/exception handling

Design Patterns

• Factory Method Pattern: Implemented to handle the creation of different types of reviews (book review, author review..). This ensures that the system can easily accommodate additional review types in the future without modifying the core logic.

  • Encourages adherence to the Open Closed principle
  • Makes the code more maintainable and readable, as review creation logic is centralized in one place

• Strategy Pattern: Implemented to allow dynamic selection of sorting algorithms (by title or author). This makes the sorting logic extensible and modular. Instead of hardcoding sorting logic, the pattern allows swapping algorithms at runtime depending on user preferences or system requirements.

  • Encourages modularity by encapsulating each sorting logic into seperate, reusable classes
  • Single-Responsibility Principle

Conway's Game of Life

V2 implementation of the Game of Life

Description:

The Game of Life is a cellular automaton devised by british mathematician John Horton Conway in 1970. It is a zero-player game, meaning that it's evolution is determined by it's initial state, requiring no further input. One interacts with the Game of Life by creating an initial configuration and observing how it evolves in discrete time steps called generations. There is no limit to the number of generations or win condition.

Rules:

The universe of the Game of Life is an infinite, two-dimensional orthogonal grid of square cells, each of which has two possible states, live or dead. Every cell interacts with it's eight neighbours, which are horizontal, vertical, or diagonally adjacent.

  • Any live cell with fewer than two live neighbours dies, as if by underpopulation
  • Any live cell with two or three live neighbours lives on to the next generation
  • Any live cell with more than three live neighbours dies, as if by overpopulation
  • Any dead cell with exactly three live neighbours becomes a live cell

The initial pattern constitutes the seed of the system. The first generation is created by applying the above rules simultaneously to every cell in the seed, live or dead; births and deaths occur simultaneously. Each generation is a pure function.

In the V2 implementation, all live cells are stored within a Set, where each cell is represented as a JSON-stringified [row,col] pair to ensure uniqueness. This data structure choice significantly improves performance by restricting computation to only the active (live) cells, resulting in a worst-case time complexity of O(n) with respect to the number of live cells, rather than the total number of grid cells.

The use of a Set also provides efficient constant-time operations for insertion, deletion, clearing, and size retrieval. These properties facilitate effective population tracking and contribute to overall performance improvements.

In contrast, the V1 implementation exhibited poor performace, with an INP score of approximately 1,200 ms. The V2 approach mitigates this issue by rendering the grid statically and updating only the necessary cell states, rather than repeatedly redrawing the entire grid and its cells each frame. This optimization results in a substantial reduction in rendering overhead and improved execution efficiency.

Casino Royale

2D RPG-style game made with Unity

Description

Casino Royale was a game I made with friends as a fourth-year project at Western University. The goal was to design and build a game with thoughtful game design principles. We had complete creative control, so we naturally used that freedom to craft a Pokémon-style casino adventure where players wage combat chips, deal damage through different gambling mini-games, and battle enemies.

Features

The World is an open environment divided into four unique domains: Ice, Sand, Forest, and Gloom. Players can interact with various NPCs and signs scattered throughout the world. Some NPCs are combat encounters that must be defeated to progress. Winning a battle rewards you with gold, which can be spent on items in the in-game shops.

The store offers a variety of items with different prices and rarities. These items can be equipped and used in combat to grant unique boosts- improving your chance, damage, health, shields, and more. Each domain has it's own gym and local boss that must be defeated to advance. Bosses become progressively harder from one domain to the next, preventing players from completing the game on their first attempt.

Network Traffic Analyzer & Anomaly Detector

Personal Cybersecurity Project - Mock SOC Detection Tool

Description

A Python based network security tool that captures live packet data, detects suspicious traffic patterns in real time, and logs structured events into Splunk for alert correlation and data visualization; mimicking a lightweight SOC detection workflow. Built as a personal cybersecurity project applying skills learned from the Google Cybersecurity Certificate , including network security, SIEM tooling, and incident response following the NIST SP 800-61 framework.

Features

• Live Packet Capture & Parsing - Captures packets in real time using Scapy, extracting IP addresses, ports, protocols, TCP flags, and traffic direction across Ethernet, IPv4, TCP, UDP, and ARP layers.

• Anomaly Detection - Three custom detection rules running continously against live traffic: port scan detection, SYN flood detection, and ARP spoofing detection, each using an interchangable rolling time window.

• Splunk Intergration - Structured JSON logs ingested into Splunk with SPL correlation searches and a real time dashboard showing multi-stage attack patterns from the same source IP.

• AI Incident Response Generator - Claude powered agent that reads alert logs and automatically produces a formal NIST SP 800-61 incident response report covering all six phases of the IR lifecycle.

• Attack Simulator - Small script that crafts and injects simulated port scan, SYN flood, and ARP spoof packets for end-to-end testing of the detection script without a real attacker.

Detection Rules Explained

• Port Scan Detection - A port scan is a method of probing a server to identify which communication ports are open, closed, of filtered, this could be the first step before an actual attack. The script detects this by tracking how many unique destination ports a single source IP contacts within a 60 second window. Once the count exceeds X number of unique ports (~15 in this case), an alert fires.

• SYN Flood Detection - A SYN flood is a type of Denial of Service (DoS) attack that overloads a server's resources by initiating-but never completing-a TCP connection. Normally, devices establish a connection using a "three way handshake". The client sends a SYN (Synchronize) packet to the server. The server responds with a SYN-ACK packet and allocates resources for the connection. The client completes the connection by sending an ACK packet. In a SYN flood, the attacker sends a barrage of SYN requests to the server. This leaves the server with countless "half-open" connections, tying up it's memory and ports until it runs out of resources and cannot accept legitimate traffic. The script detects this by counting how many TCP packets carrying only the SYN flag arrive from a single source IP within a 5 second window. If the count exceeds 50 packets, an alert fires.

• ARP Spoof Detection - ARP spoofing (also called ARP poisoning or man-in-the-middle attack) is a cyberattack in which a hacker sends fake ARP messages onto a local network. The goal is to trick a device into linking its IP address with the attacker's MAC address, allowing the attacker to intercept, modify, or block traffic. The script detects this by building a trusted IP to MAC mapping table at startup, based on the OS ARP cache. Every ARP packet is checked against this table, if a watched IP is claimed by a different MAC than what was recored, a CRITICAL alert is fired.

What I Learned

• Going into this project I had never used Scapy, never touched Splunk, and had no real experience capturing & analyzing raw network packets, besides using WireShark once in University. I had to learn how packets are structured at each layer of the network stack, how to extract meaningful fields from raw packets in real time, and how to design stateful detection logic that persists state across thousands of packets without slowing the capture down.

• The AI incident response generator was also my first time integrating an AI API directly into a Python script. building something that reads real alert data from a JSON file which gets summarized and stored as a list and dictionary for easy readability. It was my first time working/building an AI agent and was suprised by how easiy the implementation was and how it streamlined production to really bring my project together.

Technical Challenges

• tcpdump on Windows - The original design was to have tcpdump running in parallel with Scapy to write a raw .pcap backup file. This was originally set because tcpdump is more optimized and can run continous, long-term packet captures without exhausting the system's memory, unlike Scapy which is significantly more resource intensive. Consequently, tcpdump doesn't exist natively on Windows (duhhhh), which broke the capture pipeline entirely. The simple fix was to replace tcpdump with Scapy's built-in PcapWriter, which writes packets to disk as they arrive with no external dependencies.

•Windows Raw Packet Injection - The biggest challenge that left me confused was discovering that Windows blocks Scapy from injecting packets with spoofed source IPs on real network interfaces. When the attack simulator sent crafted packets with a fake source IP, Windows would rewrite or reject them before they reached the sniffer; meaning, the anomaly Detector never saw them. The fix was to route all simulated attack traffic through the Software Loopback Interface, where Windows does not apply the same restrictions.

•AI API Rate Limits - The IR report generator sends a large prompt containing all captured alert data. Both OpenAI and Google Gemini's free tiers hit quota limits immediately given the size of the payload. After having explored both free options and paid options, I ultimately decided to load funds into my OpenAI account to increase my rate limit. This wasnt ideal, as I didnt expect to be dumping some money into this project, however it was worth the results.
